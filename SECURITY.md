# Security Policy

## Supported Version

Security fixes are applied to the latest `main` branch and the current public deployment that is built from it.

## Reporting a Vulnerability

Do not open a public issue with exploit details, credentials, tokens, or proof-of-concept payloads.

Use GitHub's private vulnerability reporting flow from the repository Security tab if it is enabled. If that path is not available, open a minimal public issue asking for a private reporting channel and omit all sensitive details until a private path is established.

Please include:

- affected paths, commit SHA, or deployment URL
- impact and expected blast radius
- reproduction steps or a concise proof of concept
- mitigation ideas, if you already have them

## Disclosure Expectations

- Initial acknowledgement target: within 7 days
- Remediation timing depends on severity, exploitability, and deploy risk
- Public disclosure should wait until a fix or mitigation is available
